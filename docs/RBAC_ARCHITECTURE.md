## 🔍 权限判断流程

### 改造前
```
用户登录 → 查询 users.role → 简单判断
                ↓
            if (role == 'admin') {
                允许所有操作
            }
```

### 改造后
```
用户请求权限
    ↓
┌─────────────────────────────────────┐
│ 1. 检查用户直接权限（拒绝）           │ ← 最高优先级
│    如果拒绝 → 立即返回 false         │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 2. 检查用户直接权限（授予）           │
│    如果授予 → 返回 true              │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 3. 检查角色权限                      │
│    遍历用户所有角色                  │
│    检查角色是否有该权限              │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 4. 检查继承权限                      │
│    检查父角色权限                    │
└─────────────────────────────────────┘
    ↓
默认拒绝
```

## 📈 数据权限范围

```
┌──────────────────────────────────────────┐
│          数据权限范围类型                  │
└──────────────────────────────────────────┘

ALL (所有数据)
├─ 超级管理员
└─ 系统管理员

DEPARTMENT (本部门)
├─ 部门经理
└─ 客服人员

DEPARTMENT_AND_SUB (本部门及下级)
└─ 区域经理

SELF (仅自己)
├─ 销售人员
└─ 普通员工

CUSTOM (自定义)
└─ 通过 data_permissions 表定义
```

## 🎯 权限类型层级

```
┌────────────────────────────────────────┐
│           权限类型                      │
└────────────────────────────────────────┘

MENU (菜单权限)
├─ 控制菜单显示/隐藏
└─ 示例：customer:list

BUTTON (按钮权限)
├─ 控制页面按钮显示
└─ 示例：customer:create, customer:delete

API (接口权限)
├─ 控制 API 访问
└─ 示例：/api/customers (POST)

DATA (数据权限)
├─ 控制数据访问范围
└─ 示例：只能查看自己的客户
```

## 💡 实际应用示例

### 场景 1：销售人员权限
```
用户：张三
角色：sales (销售人员)
数据范围：SELF (仅自己)

拥有权限：
✓ customer:list      (查看客户列表)
✓ customer:detail    (查看客户详情)
✓ customer:create    (创建客户)
✓ lead:list          (查看线索列表)
✓ order:create       (创建订单)

数据限制：
✓ 只能看到 owner_id = 张三.id 的客户
✓ 只能看到 owner_id = 张三.id 的线索
✓ 只能看到自己创建的订单
```

### 场景 2：部门经理权限
```
用户：李四
角色：manager (部门经理)
数据范围：DEPARTMENT_AND_SUB (本部门及下级)

拥有权限：
✓ 继承 sales 的所有权限
✓ customer:export    (导出客户)
✓ lead:assign        (分配线索)
✓ team:view          (查看团队)
✓ report:view        (查看报表)

数据限制：
✓ 可以看到本部门及下级部门的所有数据
✓ 可以分配本部门的线索
✓ 可以查看本部门的业绩报表
```

### 场景 3：临时授权
```
用户：王五
角色：sales
临时权限：customer:export (7天后过期)

权限判断：
1. 检查 user_permissions 表
   → 发现临时授权 customer:export
   → 检查 expires_at > NOW()
   → 返回 true

7天后：
   → expires_at < NOW()
   → 临时权限失效
   → 回退到角色权限
```

## 🔐 安全性提升

### 改造前
```
❌ 权限硬编码在代码中
❌ 无法动态调整权限
❌ 缺少审计日志
❌ 无法临时授权
❌ 数据权限混乱
```

### 改造后
```
✅ 权限存储在数据库
✅ 可动态配置权限
✅ 完整的审计日志
✅ 支持临时授权
✅ 细粒度数据权限
✅ 权限继承机制
✅ 拒绝优先策略
```
